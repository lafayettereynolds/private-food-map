# Taste Map 项目状态

## 已完成

- 原生 iOS 已完成 P4-F 餐厅榜单闭环：我的榜单、新建/编辑/删除、普通/排名模式、显式拖拽排序、单项备注、自动/既有照片封面、Restaurant Detail 多榜单加入、公开/好友/私密权限、Public Profile 入口、公开详情、系统分享元数据及公开榜单餐厅加入自己的想吃。榜单引用 Global Restaurant identity，与 WantToGo 和 Visit 独立；Apple Maps-only 餐厅无需 `amapPoiId`。
- 榜单采用 SwiftData local-first + Sync V1 `restaurantList` / `restaurantListItem`，App 重启保留队列和顺序；公开列表使用 viewer-scoped query cache。Development D1 已增量应用 `0028`，真实隔离 A/B Worker E2E、10 项原生 domain 测试和两条 Simulator UI E2E 通过，Production 未访问。完整边界见 `P4_F_RESTAURANT_LISTS.md`。

- 已建立完整口味档案、饭搭子分析、推荐来源分析、本月回味、年度回味和那年今日六类统一分析分享系统；分析页与分享海报共用 `AnalysisShareData`，但使用独立的编辑式海报布局，不再直接截图页面。海报固定为 1080 × 1440，优先使用到访实拍和对应餐厅封面，支持稳定选图、真实候选内换图、保存 PNG 和系统分享，并在生成前统一过滤私人标识、精确位置和未授权消费等内容。
- 首页以地图为默认视图；桌面端与手机端均可在完整地图和完整列表间切换，地图模式保留“去过 / 想吃 / 推荐”分类栏及“查看列表”入口。
- 地图餐厅使用图片圆点和评分色环；当前位置使用圆形头像、主色外圈和尖角组成的定位气泡，与餐厅点区分。
- 地图、列表、想吃、推荐、发现和食单共用同一套餐厅详情；页面会合并同店的全部本地与历史记录以补齐商家资料，电话和营业时间有可靠数据时才展示，路线入口始终保留。
- Development 使用 `food-map-dev`，当前保留 77 家当前测试账号的已到访餐厅：杭州 61 家，另有上海、北京、广州、深圳、成都、南京、苏州和香港共 16 家跨城市测试餐厅；Production 继续使用独立的 `food-map-prod`，不会接收这些测试数据。
- Development 的个人 D1 同步默认关闭，避免云端公开测试餐厅进入当前用户的“去过”清单；发现页仍可通过独立的 Social API 读取公开测试数据。跨城市餐厅由 Development 本地种子增量补充，仅用于验证城市分布、地图缩放和跨城详情，不代表 Production 真实到访。
- 到访可记录到店/外卖、消费方式、总价或个人消费、人数、饭搭子、排队时长、菜量、性价比、推荐来源、照片、菜品、笔记及更多体验信息。
- 新增/编辑到访、添加/编辑餐厅、编辑个人资料、创建食单和手动添加小店等长表单已统一使用固定底部操作栏；表单内容独立滚动，取消与保存始终可见，并兼容手机安全区和键盘压缩后的可视区域。新增到访的详细字段继续全部可选，进入页面即可直接保存有效记录。
- 餐厅新增与到访记录入口统一复用 `PlusAction`：全局 `+` 进入餐厅搜索/添加，已知餐厅旁的 `+` 直接打开“写下这家餐厅”并新增一次 Visit；地图详情、餐厅列表、搜索结果和发现信息流保持相同语义，想吃、抽签、分享及添加好友继续使用各自独立图标。
- “各付各的”显示“我的消费金额”，不计算人均；AA/请客场景显示总价和估算人均。
- 饭搭子会复用历史输入，默认显示 5 人并可用“更多”展开全部；排队时长和体验选项使用直接点选、等宽布局。
- 菜品记录以“菜品 + 添加”作为直接入口，不显示多余的“可选”说明。
- “更多记录”位于表单末尾；适合场景支持多选和自定义，上餐时长包含 15/45 分钟等直接选项。
- “我的”页顶部采用居中的身份区：添加好友与设置分列顶部两侧，头像、昵称、Premium 标识、简介或加入时间及编辑资料居中展示；四项等宽统计固定为“我关注的 / 关注我的 / 去过 / 想吃”，并统一使用品牌色语义图标。去过与想吃均按唯一餐厅去重而不是按 Visit 数量统计，四项均可进入对应列表，顶部不展示“公开记录”；移动端保持四列，极窄屏切换为 2×2。
- “好友推荐”不再占用“我的”首页空间；点击顶部“添加好友”进入统一页面，在同一弹层中先搜索用户，再查看完整好友推荐列表。推荐仍由既有服务排除已关注、已申请、近期拒绝、自身及不可发现用户，并保留可解释理由、推荐强度和轻量添加/隐藏操作，不新增持久化字段。
- “今天吃什么”和“我的口味档案”已整理为同一行、等宽等高的紧凑入口；前者只保留“帮我挑一家”，后者只预览偏爱菜系、常选价位和少量体验特征。桌面与常规手机保持双列，极窄屏才改为单列。
- 提供 16 个动物预设头像，默认北极熊；自定义上传头像仅会员可用。
- 地图公开范围由个人页统一设置，不再在单次到访表单或历史摘要中重复展示。
- 地图列表提供独立“味觉足迹”动态流，按到访时间连续滚动，展示餐厅、评分、笔记、到访照片或菜品图片；该动态流不作为地图筛选。
- 添加餐厅的“附近餐厅”只采用浏览器高精度 GPS，在转换为高德坐标后并行检索“餐厅 / 美食 / 饭店”，去重后按实际距离排序；定位、服务异常、无结果和超时都会结束 Loading。
- 添加餐厅新增“粘贴餐厅链接”入口，可识别高德、Apple Maps、普通餐厅网页和分享文本；外部链接只作为搜索证据，候选唯一时仍需用户确认，多候选必须手动选择，低置信度只回填现有 POI 搜索，不会自动创建餐厅、自动标记去过或自动加入想吃。
- Worker 新增受身份保护的 `/api/external-place/resolve`：统一解析外部链接、限制 HTTPS、拒绝回环/内网/云元数据地址、逐跳检查重定向并限制超时、响应大小和内容类型；响应只返回确认所需的餐厅候选、置信度和推荐来源建议，不保存第三方评分、评论或照片。
- 餐厅详情可直接“加入抽签”；统一候选池最多 10 家，达到 2 家即可开始。轮盘采用餐厅图片候选标签和低饱和圆形分区，未占用位置显示“添加更多餐厅”，并支持删除、清空、候选管理、结果卡、持续转动提示音和静音。
- “发现”包含关注、为你推荐、同味之选、最新和趋势五栏；为你推荐只呈现餐厅与历史餐厅相似度，同味之选才呈现相似用户。发现推荐和地图“推荐”均支持距离、评分与排序，地图另支持城市；评分可多选，已移除废弃的标签筛选。筛选为 0 时会识别真实限制条件并给出最小有效放宽操作，数据不足、无公开内容、无关注动态和趋势样本不足使用各自独立空状态。开发环境的模拟公开到访会稳定展示 2–3 张演示餐图，以便验证信息流的双图和三图布局；正式记录不注入演示图片。
- 发现页五个分栏的餐厅动态已统一交互：左侧为点赞、评论和转发，右侧为“记录去过 / 想吃 / 加入抽签”，三项餐厅操作复用同一个组件并即时显示选中状态。点击餐厅正文、图片或名称会在当前发现页面打开完整详情，点击用户头像或昵称进入公开主页；记录到访不再切换地图，想吃与抽签不会误开详情或轮盘，关闭详情后保留原分栏和滚动位置。当前 Web 版会在本地保存互动状态与计数，刷新页面后仍然保留。
- 发现页“转发”已统一为餐厅分享：优先调用系统分享，浏览器不支持时使用轻量分享弹层和复制链接；分享内容只包含公开餐厅资料与稳定公开地址，不携带 Visit、用户、推荐证据、饭搭子、消费或内部标识，也不展示公开分享计数。公开地址可打开最小餐厅详情页。
- 推荐距离具有明确锚点：设备所在城市与浏览城市一致时使用设备位置，跨城市或定位不可用时使用当前浏览城市候选中心并明确标注；不会静默拿另一座城市的 GPS 计算距离，也不会自动突破用户选择的距离条件。
- 测试环境已有 40 个模拟用户、66 家测试餐厅、1374 条到访以及关注、好友、想吃和共同饭局数据；模拟用户包含 2024—2026 年稳定加入时间、30 个免费身份、10 个会员身份、31 条已接受好友关系和 4 个已绑定饭搭子账号场景，可用于验证好友推荐的共同好友、同城、同味与历史饭搭子信号。

- 应用内顶部品牌标识、浏览器图标、PWA/手机桌面图标与 Windows 启动快捷方式统一使用北极熊汉堡图标。
- 底栏保留“地图 / 发现 / 我的”，小型“添加餐厅”按钮固定悬在发现入口正上方。

- 价格参考区分餐厅手动参考价与真实到访中位数，并显示样本量和可信度；个人消费与总消费保持不同语义。

- 推荐 V1 已拆分个性化、同味、最新与趋势服务，支持冷启动、低样本降级、跨城市上下文和曝光/点击/想吃/抽签反馈事件。
- 餐厅详情固定为“稳定商家头图 → 我的/全部用户/好友/同味评分参考 → 用户实拍 → 我的到访概览 → 到访历史”，社交均分同时显示样本量；用户上传的到访照片不会随机替换商家主图。
- “我的食单”支持普通合集与排名榜单、拖拽排序、单项笔记、自动四宫格/自定义封面、可见范围、餐厅详情直接加入，以及可跨设备打开的稳定公开地址。
- 食单详情支持直接搜索现有餐厅并加入当前食单，已在食单内的餐厅不会重复出现；加入后可继续编辑入选理由和排序。
