# Taste Map 项目状态

更新时间：2026-08-25

## 已完成

- 首页以地图为默认视图；桌面端与手机端均可在完整地图和完整列表间切换，地图模式保留“去过 / 想吃 / 推荐”分类栏及“查看列表”入口。
- 地图餐厅使用图片圆点和评分色环；当前位置使用圆形头像、主色外圈和尖角组成的定位气泡，与餐厅点区分。
- Development 使用 `food-map-dev`，保留约 60 家测试餐厅；Production 使用独立的 `food-map-prod`。
- 到访可记录到店/外卖、消费方式、总价或个人消费、人数、饭搭子、排队时长、菜量、性价比、推荐来源、照片、菜品、笔记及更多体验信息。
- “各付各的”显示“我的消费金额”，不计算人均；AA/请客场景显示总价和估算人均。
- 饭搭子会复用历史输入，默认显示 5 人并可用“更多”展开全部；排队时长和体验选项使用直接点选、等宽布局。
- 菜品记录以“菜品 + 添加”作为直接入口，不显示多余的“可选”说明。
- “更多记录”位于表单末尾；适合场景支持多选和自定义，上餐时长包含 15/45 分钟等直接选项。
- 个人页包含头像、关注我的、我关注的、回顾、口味档案、数据设置、账号隐私以及“今天吃什么”；关注数字可进入真实用户列表，继续点击可查看对方公开资料。
- 提供 16 个动物预设头像，默认北极熊；自定义上传头像仅会员可用。
- 地图公开范围由个人页统一设置，不再在单次到访表单或历史摘要中重复展示。
- 地图列表提供独立“味觉足迹”动态流，按到访时间连续滚动，展示餐厅、评分、笔记、到访照片或菜品图片；该动态流不作为地图筛选。
- 添加餐厅的“附近餐厅”只采用浏览器高精度 GPS，在转换为高德坐标后并行检索“餐厅 / 美食 / 饭店”，去重后按实际距离排序；定位、服务异常、无结果和超时都会结束 Loading。
- 餐厅详情可直接“加入抽签”；统一候选池最多 10 家，达到 2 家即可开始。轮盘采用餐厅图片候选标签和低饱和圆形分区，未占用位置显示“添加更多餐厅”，并支持删除、清空、候选管理、结果卡、持续转动提示音和静音。
- “发现”包含关注、为你推荐、同味之选、最新和趋势五栏；为你推荐只呈现餐厅与历史餐厅相似度，同味之选才呈现相似用户。发现推荐和地图“推荐”均支持距离、评分与排序，地图另支持城市；评分可多选，已移除废弃的标签筛选。筛选为 0 时会识别真实限制条件并给出最小有效放宽操作，数据不足、无公开内容、无关注动态和趋势样本不足使用各自独立空状态。开发环境的模拟公开到访会稳定展示 2–3 张演示餐图，以便验证信息流的双图和三图布局；正式记录不注入演示图片。
- 推荐距离具有明确锚点：设备所在城市与浏览城市一致时使用设备位置，跨城市或定位不可用时使用当前浏览城市候选中心并明确标注；不会静默拿另一座城市的 GPS 计算距离，也不会自动突破用户选择的距离条件。
- 测试环境已有 40 个模拟用户、66 家测试餐厅、1326 条到访以及关注、好友、想吃和共同饭局数据；当前测试账号有 10 个我关注的、9 个关注我的。
- 餐厅详情以商家图片开始，提供我的评分、全部用户、好友、同味四个圆形评分参考；大圆按评分区间显示对应颜色，小圆只显示历史餐厅样本数或参与用户数，空状态在圆内使用统一图案和“暂无数据”。三枚“去过 / 想吃 / 抽签”快捷按钮位于店名右侧，评分参考后展示用户实拍与包含体验维度的到访概览，再保留可展开、可滚动的到访历史；发现信息流里的公开实拍会同步出现在同一餐厅详情中。
- 已建立全局视觉 Token：主色 `#506C8C`、深主色 `#344F69`、浅主色背景 `#EDF2F6`，并统一主次文字、页面背景、卡片、分割线、未选中和低频暖色强调。
- 应用内顶部品牌标识、浏览器图标、PWA/手机桌面图标与 Windows 启动快捷方式统一使用北极熊汉堡图标。
- 底栏保留“地图 / 发现 / 我的”，小型“添加餐厅”按钮固定悬在发现入口正上方。
- 地图与餐厅身份已通过 Provider / Global Restaurant ID 服务解耦；当前继续使用高德，但业务组件不再直接依赖高德返回结构。
- Local-first 同步改为显式操作队列、增量游标、幂等合并与失败重试；图片存储使用可替换 Provider、缩略图和本地缓存，现阶段默认 Google Drive。
- 会员权限由服务端 Entitlement 决定，支持后台赠送、到期、撤销与审计；免费/会员差异已用于自定义头像和完整食味年鉴内容。
- Visit 评分可为空，填写时支持半星；所有聚合继续显示 10 分制，未评分记录不再错误参与均分。
- 价格参考区分餐厅手动参考价与真实到访中位数，并显示样本量和可信度；个人消费与总消费保持不同语义。
- 口味档案 2.0 与推荐共用同一套有效到访口径，包含菜系、价位、高分/踩雷特征、场景、复购、评分习惯、置信度和公开摘要。
- 推荐 V1 已拆分个性化、同味、最新与趋势服务，支持冷启动、低样本降级、跨城市上下文和曝光/点击/想吃/抽签反馈事件。
- 餐厅详情固定为“稳定商家头图 → 我的/全部用户/好友/同味评分参考 → 用户实拍 → 我的到访概览 → 到访历史”，社交均分同时显示样本量；用户上传的到访照片不会随机替换商家主图。
- “我的食单”支持普通合集与排名榜单、拖拽排序、单项笔记、自动四宫格/自定义封面、可见范围、餐厅详情直接加入，以及可跨设备打开的稳定公开地址。
- “本月回顾”和年度“食味年鉴”由独立 ReviewService 动态生成；消费统计使用个人实际支出，分享摘要会剔除饭搭子、来源、照片和真实金额等私密信息。
- 点击我关注的或关注我的用户会进入独立公开资料视图，立即显示占位资料、加载公开记录，并提供明确返回入口；不会再套用本人关注数字和管理入口。
- 发现页进入用户资料后会返回原来的发现分栏；食单餐厅可在当前上下文打开完整详情，关闭详情后仍回到原食单，不会跳回地图或退出食单。餐厅列表统一显示评分、参考价格、到访次数、城市、详细地址和三枚快捷操作。
- “我想去”录入会随 POI 一起保留名称、详细地址、图片、电话与营业时间；去过餐厅详情的头部信息、评分参考、到访历史和底部操作在窄屏中不会再互相覆盖。
- Development 启动会先增量应用本地 D1 migration，再按需启动测试服务；桌面测试版启动文件已按实际流程验证。Production D1 当前已应用到 `0014_restaurant_contact_details.sql`。
- “我的数据”已增加“饭搭子分析”：页面包含关系摘要、搜索、饭搭子列表和单人完整洞察，使用简洁图标呈现共同次数、不同餐厅、最近记录、消费、菜系、常去餐厅、用餐方式、城市和共同记忆；头像统一为圆形细黑线。统计仍只基于当前用户自己的有效 Visit，只有 3/6 次以上才逐级开放基础/完整洞察，绑定真实用户但缺少明确授权时不会读取或推断对方私密数据。
- “我的数据”已增加“推荐来源分析”：以餐厅首次有效来源作为该餐厅的发现来源，同一餐厅的重复 Visit 只用于评分、复购和消费结果验证，不重复计算推荐家数；页面展示来源样本、真实到访结果、高低分命中、复购、菜系与可追溯餐厅证据，3/6/10 家分别进入轻量、低置信和稳定阶段。
- 饭搭子与推荐来源分析均使用独立 Service 动态聚合，不把统计结果写回数据库；来源表现只作为未来推荐中的弱信号，不能越过距离、预算、场景和长期口味等明确条件。

## 待完成或待验证

- 正式环境不会自动写入模拟用户；发现页在真实用户和公开数据逐渐增加前可能内容较少。
- 会员资格目前由服务端字段控制；还没有接入真实的订阅或付费系统。
- 好友、共同饭局和推荐仍是轻量第一版，未扩展为消息推送或复杂社交动态系统。
- 已绑定饭搭子的双人评分、双方口味相似度和“我们都想吃”仍需权限完备的跨用户数据接口后再开放；当前只展示“基于我的记录”的可信结果。
- 推荐来源的“收录 → 想吃 → 到访”转化率暂不展示，因为现有历史记录没有稳定的来源获得时间，无法保证时间归因正确。
- 后续 iOS 客户端尚未开始；现有模型和同步接口继续保持平台无关。
