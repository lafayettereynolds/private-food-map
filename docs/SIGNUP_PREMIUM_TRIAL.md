# Signup Premium trial

Implemented 2026-09-08 in the current integration checkout. This is a Taste Map entitlement, independent of Apple introductory offers and StoreKit transactions. It requires an explicit user claim; registration itself does not grant access.

## Database and authority

Apply `migrations/0037_signup_trial.sql` before deploying the Worker routes. The existing `membership_entitlements` history is the permanent claim record; no client-writable `trial_claimed_at` field is added. A partial unique index on `user_id WHERE source = 'signup_trial'` covers active, expired and revoked rows. Triggers retain historical trial rows and prevent rewriting their account, source, start, end or lifetime facts, or undoing revocation.

A single `INSERT ... ON CONFLICT ... DO NOTHING RETURNING` wins under concurrent requests. Eligibility reads are advisory; the claim does not rely on a prior read. Dates are generated by the Worker and the term is exactly 604800 seconds. No Apple transaction, purchase request, payment method or renewal schedule is created.

Eligibility follows the requested rules: any authenticated account with no historical signup trial is eligible, including existing accounts or current subscribers. There is no invented account-age cutoff. Account identity comes from the established authenticated session; client body fields and test identities are rejected.

## APIs

- `GET /api/v1/me/premium-trial-eligibility`: `{ apiVersion: 1, userId, eligible, trialDays: 7 }`.
- `POST /api/v1/me/premium-trial/claim`: empty body or `{}` only. Returns `{ apiVersion: 1, userId, isPremium: true, source: "signup_trial", expiresAt, membership }`. `membership` is the full authoritative `/me/entitlements` representation, so an existing Apple or Gift entitlement retains its display precedence and expiry.
- Repeat claim: HTTP 409, including expired/revoked history. Unauthorized: 401; client-supplied authority/date fields: 400; unsupported method: 405. Responses use `Cache-Control: no-store`.

## Membership and UI

The existing `readEffectiveMembership` remains the shared server access authority. Any currently active, started and unexpired entitlement grants Premium; lifetime records remain supported. `signup_trial` maps to fixed-term in the versioned contract. Source aliases `app_store_subscription` and `promotion` are accepted alongside existing monthly/annual/yearly and `promo` source values; existing records and SKUs are not renamed.

Native `PremiumEntitlementService` validates user scope and session generation, serializes local claim clicks, drops superseded refreshes, immediately applies the claim response's combined membership and updates the scoped cache. Trial eligibility is only fetched from the server and is never trusted from local storage. Expired cached trials fail access checks without waiting for the network. Open Premium pages refresh membership every minute and on their existing entry/lifecycle paths.

The existing Native `PremiumPaywallView` and shared React `TasteMapPremiumPage` show:

- 免费体验 Premium 7 天
- 无需订阅，不会自动续费
- 免费领取 7 天

Successful claims hide the button and show the expiry date. An expired account uses the normal monthly/annual purchase section. Existing subscription IDs remain `com.lafayette.tastemap.premium.monthly.v1` and `com.lafayette.tastemap.premium.annual.v1`.

Hybrid uses additive typed `premium.trialEligibility` and `premium.claimTrial` bridge methods backed by the same Native service. No credentials or client entitlement mutations cross the bridge. The Browser adapter requests the real endpoint and fails without an accepted server session; this change does not add Browser Apple authentication. Production remains NATIVE_PRIMARY, with no navigation redesign.
