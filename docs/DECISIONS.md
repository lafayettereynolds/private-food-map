# Taste Map 产品与技术决策

更新时间：2026-08-22

- App 启动后首先显示地图；地图与列表采用两个完整模式，地图模式仍保留餐厅分类栏和始终可见的“查看列表”入口。
- “味觉足迹”是列表模式中的独立动态流，不是地图筛选；按 Visit 时间展示笔记与照片，并允许持续滚动浏览。
- 当前位置使用“头像 + 小尖角”的定位气泡；餐厅继续使用圆形图片标记，两个体系不混用。
- 主色使用克制的蓝色/蓝黑色；表单优先使用等宽、直接点选和清晰分组，减少下拉框与不规则换行。
- 表单中的可选附加项用明确动作入口表达：菜品直接显示“添加”，饭搭子默认限量展示并通过“更多”展开。
- “适合场景”描述单次 Visit，允许同时选择多个场景并可自定义；旧单值字段只用于兼容。
- 单次到访不单独管理可见性；用户在“我的”中统一选择仅自己、互相关注或公开。
- 关注关系只在个人页显示“关注我的”和“我关注的”；互相关注作为“我关注的”列表状态，不单独设入口。
- “今天吃什么”转盘属于“我的”中的工具模块，不占独立底部导航入口。
- 免费用户可使用全部预设头像；只有服务端确认的会员可上传自定义头像，客户端不能自行提升会员等级。
- Web 仍是当前主要客户端，但数据模型、同步接口、认证与图片引用不得绑定到特定 Web UI，以便未来 iOS 复用。
- 只有字段、数据库结构或同步协议变化时才检查 migration；纯 UI、布局、颜色和文案修改跳过数据链路检查。
