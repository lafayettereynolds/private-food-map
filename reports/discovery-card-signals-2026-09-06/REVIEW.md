# Discovery reason tags, social actions and honest recommendation signals

Scope: latest Lafayette-approved reason-tag and social-weight correction plus dual recommendation signal semantics. Existing dirty changes were preserved. No Map/GPS implementation, App Shell, Visit editor, staging, build, installation or production deployment was performed by this subtask.

## Implemented

- Shared React `TasteMapRecommendationReasons`: trimmed/deduplicated independent tags, intrinsic text width, shared 5/6/3/6/11 radius/inset/gap/type tokens, no bullet or enclosing outline. Following root visual review, long raw reasons now use a literal 12-grapheme excerpt with an explicit ellipsis; each chip stays on one line and at most 160px wide. One shared 44px region opens all complete, unchanged reasons in the existing modal. This keeps the original long test sentence intact and verifiably reachable while removing the dominant full-width two-line box. Native Core uses the same excerpt/combined-target/full-explanation mechanism.
- Shared `TasteMapSocialAction`: bare Like/Comment/Share icons, quiet count, true minimum 44px target, preserved callbacks/pending/pressed state, exact accessible count and restrained dark-mode selected colors. Native Like/Comment/Share labels reuse the Core primitive. Right-hand Restaurant action controls and Visit rating semantics remain in their existing owners.
- Shared `TasteMapRecommendationSignal`: existing `personalTastePercent` means `口味匹配度`, with dashed neutral styling and a working explanation dialog. Invalid/missing numeric evidence is `积累中`; no percentage is parsed from reason prose. Validated, sufficiently supported, unexpired model output with an explicitly approved positive-feedback definition can use the separate solid `喜欢概率` mode.
- Optional `calibratedLikeProbability` fields pass through TypeScript interfaces and Native remote/cache/bridge DTOs. They preserve model/calibration versions, approved target definition/version, explicit calibration/evidence status, validation sample count and expiry. No production producer/model exists. Isolated test attestations exercise the channel only and are not model evidence. No liking threshold is inferred from 7.5 public-feed eligibility or owner record counts.
- A real Browser city bug found by the probe is fixed under root authorization: `[市州地区]$` had reduced `杭州` to `杭`, so `杭州` and `杭州市` did not match. `restaurantCityComparisonKey` now lives with the shared Restaurant-city helpers and removes only a complete optional Chinese `市` suffix. Recommendation filter and `sameCity` share it. Follow-up city-option work may reuse it.
